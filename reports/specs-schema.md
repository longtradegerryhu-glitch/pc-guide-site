# 21 品类 specs 字段清单（ORD-06 第 0 批定义稿）

> 机器可读定义：`js/specs-schema.js`（`window.PC_SCHEMA`）。本文件由 `node tools/schema-doc.cjs` 生成，**勿手改**。
> 状态：第 1 批已接线（ORD-14）。定义在本文件，解析在 `tools/specs-derive.cjs`，产物写进 `js/models-data.js` 的 `specsObj`，搜索与第 4 批对比表读同一份。

**排序原则**：按用户选购决策顺序 —— 硬约束（装不装得上）→ 性能 → 体验 → 外观。
不是按现有 specs 的分号位置排。现有位置实测不可用：显示器 3~12 段不定长，拓展坞 1~9 段，按索引对齐必然把「亮度」和「噪音」排进同一行。

**列含义**

| 列 | 含义 |
|---|---|
| 类型 | 数值=可比较排序；枚举=可分组筛选；布尔=可开关；文本=仅展示不参与对比 |
| 必填 | ☆ 表示批次一必须补齐 |
| 来源 | `解析` = 现有 specs 文本能抽出来；`补录` = 现库没有，必须外部核验 |
| 实测 | dry-run 在真实数据上的硬命中数（分子=命中，分母=该品类款数）。空=该品类未纳入必填低覆盖清单 |
| 搜索词 | 该字段补上后应当能响应的查询。**这一列是本次 schema 的重点**：字段存在但用户搜不到，等于没做 |

## 与旧结构的关系

旧结构是 `specs: "分号分隔的自由文本"`。新结构是 `specsObj: {字段: 值}`，**原 specs 字符串保留**用于降级显示。
两者不是替代关系，是「机器读的」与「人读的」并存 —— 详见 `reports/specs-migration-plan.md`。
